# คู่มือทดลองใช้ Phase 1

## สิ่งที่ใช้ได้

Login, คลังวิดีโอ, อัปโหลดและตรวจ MP4, Preview/Download แบบต้องเข้าสู่ระบบ, คอนเทนต์และ Caption สามช่องทาง, รายการเพจ/ช่อง, ส่งตรวจ/อนุมัติพร้อม Revision, งาน Facebook ส่วนตัวสองวิธี, ดูพื้นที่, เปลี่ยนรหัสผ่าน และ Audit Logs

ยังไม่เปิด AI Generation, OAuth, Auto Publishing, Scheduler ที่ส่งจริง, Retry ไป Social, Analytics, Revenue หรือ NAS/Google Drive ไม่มีการดึงยอดปลอมมาแสดงใน Dashboard

## ลำดับทดลองแนะนำ

1. เข้าสู่ระบบด้วยบัญชีที่สร้างตอนติดตั้ง
2. ไป **บัญชีและเพจ** เพิ่ม Facebook Page ด้วย Page ID ตัวเลข และ YouTube ด้วย Channel ID ที่ขึ้นต้น UC ตามด้วย 22 ตัวอักษร ไม่ใช่ชื่อ @handle
3. รายการเหล่านี้เป็น “รอเชื่อมต่อ” เพื่อเตรียมคอนเทนต์ ไม่ใช่หลักฐานว่าระบบมีสิทธิ์โพสต์
4. ไป **คลังวิดีโอ** เลือก MP4 แนวตั้ง 9:16 ความยาว 30–60 วินาที Video H.264 เสียง AAC หรือไม่มีเสียง อัปโหลดและรอผลตรวจ
5. กด **สร้างคอนเทนต์** จากคลิป เลือก Facebook Page หนึ่งเพจ และ YouTube หนึ่งช่อง
6. สำหรับทดลอง Phase 1 เลือก Facebook ส่วนตัวเป็น **อัปโหลดเป็นโพสต์ใหม่**
7. ใส่ Caption และ Hashtags แยกแต่ละช่องทาง พร้อม Title/Privacy/Audience ของ YouTube และข้อมูล Synthetic Media ตามคลิปจริง
8. เวลาที่ต้องการเผยแพร่เว้นว่างได้ หากกำหนด เวลาเป็น Asia/Bangkok และต้องยังไม่ผ่านไปตอนอนุมัติ ยังไม่มีการส่งจริงตามเวลาใน Phase 1
9. กด **บันทึกร่าง** → ตรวจ Preview/ข้อความ → **ส่งตรวจอนุมัติ**
10. ตรวจปลายทางและค่าทั้งหมด เลือกช่องยืนยัน แล้วกด **อนุมัติ Revision**
11. Facebook Page/YouTube จะแสดง “รอเชื่อม API ใน Phase 2” ระบบยังไม่ได้อัปโหลดไปสองช่องทางนี้
12. ในส่วน Manual กด Download MP4, Copy Caption และ Open Facebook จากนั้นโพสต์ด้วยตัวเอง
13. กลับมาใส่ URL ของโพสต์ส่วนตัวและเวลาที่โพสต์จริง ยืนยันและกด **Mark as Published** เฉพาะเมื่อโพสต์แล้วจริง
14. ระบบแสดง “ผู้ดูแลยืนยันแล้ว” และเก็บ Audit ไม่ถือว่าได้ตรวจโพสต์ด้วย API

## วิธีแชร์จากเพจ

เลือก SHARE_PAGE ได้ต่อคอนเทนต์ แต่ต้องรอ Page เผยแพร่สำเร็จก่อนจึงเปิดการยืนยัน Manual วิธีนี้จึงรอ Phase 2 ในการทดลองปัจจุบัน ระบบไม่สร้างโพสต์ Page หรือสถานะ PUBLISHED จำลองเพื่อให้ปุ่มทำงาน

เมื่อใช้วิธีนี้ในอนาคต ยอดวิวและรายได้ของ Page จะยังเป็นของ Page ไม่ถูกคัดลอกเป็นยอดของโปรไฟล์ส่วนตัว

## การแก้ไขและป้องกันข้อมูลซ้ำ

- ไฟล์เดียวกันที่ Hash ตรงกันจะใช้ Media Asset เดิม ไม่กินพื้นที่เก็บสำเนาซ้ำ
- หนึ่ง Asset ใช้สร้าง Content ได้หนึ่งรายการ เปลี่ยน Caption/เลือกเพจให้ใช้รายการเดิมก่อนเผยแพร่
- เมื่อแก้ร่าง Revision เพิ่มและต้องส่งตรวจ/อนุมัติใหม่ Snapshot เก่าเก็บเป็นประวัติ
- เปิดฟอร์มค้างไว้แล้วมีการแก้ไขจากอีกแท็บ ระบบปฏิเสธ Revision เก่า ให้โหลดข้อมูลล่าสุด
- เมื่อยืนยัน Manual แล้วไม่ให้เปลี่ยนไฟล์ Caption หรือปลายทางของ Content นั้น
- Disable บัญชีไม่ลบประวัติ และไม่ทำให้บัญชีนั้นพร้อมเผยแพร่ ต้องเปิดก่อนเลือก/อนุมัติ

## พื้นที่และการสำรอง

Dashboard/Settings แสดงไฟล์ในคลังของแอปและวงเงินที่ตั้งใน Config ไม่ใช่ Quota คงเหลือจริงของ Hosting ไม่มีการลบอัตโนมัติ เมื่อใช้ 80% ขึ้นไปแสดงคำเตือน และปฏิเสธ Upload ที่จะเกินวงเงิน

ใช้ Control Panel ตรวจพื้นที่เว็บอื่นและ Backup ด้วย หากต้องเพิ่มพื้นที่ให้ปรับวงเงินหลังดูพื้นที่จริง หรือวางแผนย้ายผ่าน Storage Adapter ใน Phase ถัดไป อย่าย้าย/ลบไฟล์ใน Media Directory เอง เพราะ DB ยังอ้างตำแหน่งเดิม

ข้อมูลหน้ารายการแสดงล่าสุดไม่เกิน 100 รายการใน Phase 1 จึงเหมาะกับช่วงทดลอง รุ่นถัดไปต้องเพิ่ม Pagination/Search ก่อนสะสมงานจำนวนมาก
